1. title
upload-artifacts-to-firebase: Deterministic Exfiltration of Firebase Deployment Credentials and GITHUB_TOKEN via Preserved Tar Symlinks

2. exact source
Unpacked `deploy-artifact.tar.gz` from `unsafe-artifact.zip` (which is fully attacker-controlled via the unprivileged PR build).

3. exact sink
- `tar -xvzf "$extractDir/deploy-artifact.tar.gz" -C '${{inputs.firebase-public-dir}}'` in `github-actions/previews/upload-artifacts-to-firebase/action.yml` (which blindly extracts and preserves an attacker-crafted symlink to outside the deployment directory).
- `FirebaseExtended/action-hosting-deploy` which calls the Firebase CLI, traversing the symlink due to `glob`'s `follow: true` configuration, and uploading the files to the public Firebase preview URL.

4. trust boundary crossed
An unprivileged PR build injects an attacker-controlled tarball that is subsequently extracted by a privileged `workflow_run` action. The privileged action deploys the contents to a public URL, inadvertently exposing the privileged runner's local filesystem—including deterministic files populated by the privileged workflow—to the internet.

5. strongest defensible impact
**Deterministic disclosure of files created by the privileged workflow itself.**
By embedding a symlink to `/tmp` in the tarball, an attacker can exfiltrate the temporary Google Application Credentials (GAC) JSON file generated by `FirebaseExtended/action-hosting-deploy`. By embedding a symlink to `/home/runner/work/...`, the attacker can exfiltrate the `GITHUB_TOKEN` embedded in `.git/config`. These credentials provide the attacker full access to the Firebase project (control of deployment behavior, overwrite capabilities, and cross-PR/cross-branch/cross-repo impact) and the GitHub repository privileges granted to the token.

6. what is already proven
- GNU `tar` preserves symlinks correctly during extraction without error, provided they do not attempt path traversals directly in the tar header (`../`).
- The Firebase CLI `glob` uses `follow: true` and will successfully traverse and upload directories outside of the public directory (like `/tmp` or `/etc`), provided they do not trigger OOM/infinite loops like `/` or `/proc` do.
- `extract-artifact-metadata.js` securely prevents reading files outside the directory, so the exfiltration strictly relies on the Firebase Hosting deploy step.

7. what is still unproven
- The exact path to the `.git/config` or `/tmp` directory in a live GitHub Actions runner, which can vary slightly but is easily guessable or discovered by listing parent directories or `/tmp` contents entirely.

8. classification: reportable

9. next best PoC step
Submit a PR containing an artifact with two symlinks: `leak-tmp -> /tmp` and `leak-git -> ../../../.git` (or the equivalent runner path) within `deploy-artifact.tar.gz`, then review the generated Firebase preview URL to demonstrate that the Firebase service account JSON and `GITHUB_TOKEN` are publicly readable.

---

**Single strongest reportable framing:**
Deterministic Exfiltration of Firebase Deployment Credentials and Privileged GITHUB_TOKEN via Preserved Tar Symlinks in `upload-artifacts-to-firebase`.

**Single strongest but still unproven escalation path:**
Exfiltration of `/tmp` provides the Firebase Service Account JSON (created by `action-hosting-deploy`), granting full control over the Firebase project and all other previews/production hosting, yielding cross-PR and cross-repo impact.

**Top 3 dead leads to abandon:**
1. **PR mixup via artifact metadata forgery:** The attacker completely controls the artifact, so "forging" the PR number is just basic CI misuse and provides no real tamper primitive beyond a confused deputy that can only comment on a PR, not steal secrets.
2. **Arbitrary file overwrite via `tar -xvzf`:** GNU tar safely strips `../` and absolute paths, meaning the extraction step cannot overwrite `firebase.json` or other files outside the intended directory.
3. **Exfiltration via `extract-artifact-metadata.js`:** The script uses `fs.promises.realpath` which securely resolves symlinks and throws an error if the path escapes the intended directory, killing this as a read primitive.
